# 循练 H5 体验原型

这是「循练」AI 健身管理产品的**静态前端、虚构数据交互演示**，规则参照 Skill V1.3.4。它没有 AI 后台，不采集真实健康资料，不提供真人跟练处方。GitHub Pages 从 `main` 发布；目前线上稳定版本为 **V0.2A**。

## V0.2A（已发布、已完成 iPhone 手工验收）

- 7题单步访谈、客户画像、训练日结构展示。
- 手机端按钮操作、60/40分钟**示意时间预算**、三天折叠训练卡。
- 已通过 8种基础场景逻辑检查，以及 iPhone 的访谈、预算和折叠卡实机验收。

## V0.2B（仅在 `feature/v0.2b-log-driven-adjustments` 开发分支）

### 一次日志驱动的模拟复盘

1. 新客户的四个动作任务默认均为 **「未记录」**，不能未经操作就当作完成；用户可以选「完成 / 部分完成 / 未做 / 未记录」。
2. 保存时生成**本次会话内的快照**，记录四个动作状态、示例用时、示例吃力程度及模拟反馈原因，不会上传。
3. 复盘页首先读取**已保存的日志快照**，按固定、可审查的规则给出决策标签、日志依据、处理边界及下一次「模拟展示」的方向。
4. 决策优先顺序：原始风险阻断 → 新出现的持续不适 → 资料或场地不齐 → 疲劳或过度吃力 → 器械缺失 → 核心动作未记录 → 时间不足 → 部分完成或漏做 → 全部核心项目完成但**仍不因一次日志自动加量**。
5. 调整过任何动作、时间、吃力程度、反馈原因，会立即使旧保存快照失效；需重新保存后重新得出结论。更改虚构画像或切换客户会清理原有记录。
6. 原有五种「独立情境演示」仍可用，但和日志驱动决策分别显示，不再冒充来自日志的结论。
7. 导出的纯文本反馈只增加规则**代号**，不包含用户真实疾病、负重记录或任何身份信息。

### 验证记录（代码级，不是手机实机或真人健身验证）

- JavaScript 语法检查通过。
- **21/21** 个规则单元场景通过：风险阻断、疼痛优先、器械问题、缺失记录、恢复不佳、40/60分钟超时、未完成与完工不自动加量等。
- **18/18** 个模拟交互场景通过：七题访谈、未知初始值、保存、自动复盘、修改失效、重新保存、独立事件隔离、切换案例清空等。
- 上述数据是浏览器逻辑模拟，不代表真实浏览器/iPhone 体验，也不是教练或医学专业审核。
